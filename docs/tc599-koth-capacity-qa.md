# TC-599: KoTH 최대 74팀 QA

확정된 대회 최대 팀 수 74팀에서는 TC-599를 통과한다. 한 부문에 모든 팀이 몰리는 경우에도 관리자 KoTH 목록 조회와 점수 지급이 정상 동작한다.

## 검증 범위

- 기준 main: `9ace8f1e1d493b5c58807488eca14a276822049e`
- 부문별 팀 수 0~74개 전체: 배점 개수, 양의 정수, 순위별 엄격한 감소, 1위 40점과 마지막 지급 순위 1점을 확인했다. 1~3팀인 부문은 지급 순위가 하나여서 40점을 지급한다.
- 내부/외부 팀 수 `74/0`, `0/74`, `25/49`, `37/37`: `GET /api/v1/admin/koth/challenges`의 200 응답과 부문별 배점표를 확인했다.
- 내·외부가 섞인 원본 순위에서 각 부문별 실제 지급액, 지급 제외 순위, 지급 시점 팀 수 스냅샷을 확인했다.
- 같은 구간 재수집 시 중복 지급되지 않음을 확인했다.
- 비정지 내부 74팀과 정지 내부 8팀을 함께 등록해 정지 팀이 배점 계산의 팀 수에서 제외됨을 확인했다.

## 결과와 한계

Python 3.11.7 / Django 5.2.17 / 로컬 PostgreSQL의 전용 테스트 DB에서 실제 마이그레이션을 적용한 후 신규 테스트 7개와 기존 관련 테스트 11개, 총 18개를 실행해 모두 통과했다. 외부 채점 서버 응답은 모의했으며 운영 DB의 실제 팀 수나 배포 상태는 확인하지 않았다.

재현 명령(전용 테스트 DB와 유효한 로컬 환경변수 필요):

```powershell
python manage.py test apps.koth.test_scoring_capacity apps.koth.tests.KothRankPointTests apps.koth.tests.KothScorePollingTests apps.koth.tests.KothApiTests.test_internal_token_verification_and_team_listing
```

## 잔존 결함과 운영 조건

`rank_points(81)`은 40개 순위에 40~1점을 배정하지만, `rank_points(82)`는 41개 순위에 서로 다른 40~1점을 배정할 수 없어 `ValueError`를 발생시킨다. 이 경계는 테스트에 명시했다. 82팀 이상일 때 관리자 목록 500과 점수 지급 실패가 발생하는 결함은 해결되지 않았다.

이번 대회 최대 74팀 조건에서는 해당 결함이 대회 진행을 차단하지 않는다. 이 PR은 점수 계산 방식이나 팀 수 제한을 변경하지 않는다. 배점 기준은 실제 응답 팀 수가 아니라 **부문별 비정지 등록 팀 수**이므로 테스트용 팀도 포함된다. 74팀이라는 운영 조건은 이 수를 기준으로 유지해야 한다.
