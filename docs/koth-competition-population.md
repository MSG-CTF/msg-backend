# KOTH 참가팀과 운영 검증팀 집계

대회 운영 기준은 최대 75팀이며 팀당 두 명이면 참가자는 150명이다
배점의 기준은 부문별 참가팀 수이고 회원 수는 별도로 관리한다
75팀의 지급 순위는 상위 37개이며 1등 40점·마지막 지급 순위 1점·순위별 서로 다른 양의 정수라는 기존 계산을 유지한다

## 집계 기준

정지되지 않은 팀 중 기존 미리보기·운영 검증 제외 표식에 등록된 팀 ID를 뺀다
관리자 KOTH 목록의 배점표, 게임 서버에 제공하는 팀 목록, 지급 시점의 팀 수 스냅샷이 같은 기준을 사용한다
같은 팀의 표식이 여러 문제에 있어도 한 팀으로 처리하며 삭제된 검증팀의 보관 표식은 참가팀 수에 영향을 주지 않는다

점수 응답을 받은 뒤 표식이 추가된 경우에도 지급 트랜잭션 안에서 제외 대상을 다시 읽는다
검증팀은 지급 대상에서 빠지며 남은 참가팀은 각 부문의 순위로 다시 계산한다
이미 지급 완료된 구간은 저장된 응답·배점 스냅샷을 보존하고 재수집 때 추가로 지급하지 않는다

## 운영 검증팀 등록

검증팀을 생성한 작업의 원장에 팀 ID·이름·소속 사용자 ID를 함께 기록한다
KOTH에서 제외할 때는 해당 원장과 현재 DB의 세 값을 모두 대조하고 팀 행을 잠근 상태에서 등록한다
이름의 접두사나 팀원 수로 검증팀을 추정하지 않는다

제외 표식은 기존 KothPreviewToken에 관리자 없이 키 버전 0으로 기록하며 원문을 보관하지 않는 임의 해시를 사용한다
관리자나 현재 키 버전이 없는 표식은 토큰 인증을 통과할 수 없으며 실제 검증팀의 로그인 권한·정지 상태·소속 사용자와 별개다
등록 사유·원장 해시·대상 ID·변경 전후 집계는 관리자 감사 이벤트에 남긴다
일반 참가팀의 소속이나 점수를 변경하지 않으며 진행 중인 부하 검증의 팀·사용자·실행 자료는 소유 작업에서 정리한다

## 회귀 검증

- 참가 75팀·150명에 검증용 75팀을 추가한 관리자 목록 조회가 200이며 지급 순위는 37개
- 게임 서버용 목록도 참가 75팀만 제공
- 중복 표식·정지 팀·삭제된 검증팀의 보관 표식을 함께 대조
- 실제 로컬 HTTP 점수 응답과 PostgreSQL 정산에서 검증팀 제외·부문별 배점·구간 재시도 중복 지급 방지 확인
- 응답 수신 후 추가된 제외 표식도 잠근 팀 스냅샷에서 반영

실제 부문별 참가팀이 82개 이상이면 기존 40점 안에서 모든 지급 순위에 서로 다른 양의 정수를 배정할 수 없는 제약이 계속 적용된다
이 변경의 범위는 75팀 운영 기준에서 검증팀을 분리하는 것이며 배점 공식이나 실제 참가팀의 분류를 바꾸지 않는다
