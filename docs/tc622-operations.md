# TC-622 암호화 운영

서비스 키는 systemd 암호화 자격증명에 저장하고 앱에는 tmpfs의 읽기 전용 파일로 전달한다
앱 키 원문을 Compose 환경 파일이나 Docker 환경설정 또는 DB 백업에 넣지 않는다
복구용 age 비밀키와 이전 서비스 키는 별도 복구 서버의 암호화 자격증명에 보관한다
운영 서버에는 age 공개 수신자만 둔다

## 내부 TLS

PostgreSQL은 ssl=on과 hostssl 규칙을 사용하고 hostnossl 접속을 거절한다
앱의 POSTGRES_SSLMODE는 verify-full이며 신뢰 CA를 명시한다
Redis는 평문 포트를 끄고 TLS 포트만 제공한다
앱은 rediss URL과 CA 및 호스트 이름 검증을 사용한다
DATASTORE_TLS_REQUIRED를 켜 누락된 검증 설정으로 시작하지 못하게 한다
인증서의 만료 30일 전 갱신하며 CA 비밀키는 복구 서버에서만 사용한다

## 백업과 복원

배포 전 pg_dump 결과를 gzip과 age로 연결하여 디스크에 평문 중간 파일을 쓰지 않는다
암호화한 파일과 압축 원문의 SHA-256 검증 메타데이터를 백업 폴더에 보관한다
이전 압축 백업은 별도 복구 서버에서 전부 복호화하고 해시를 대조한 후 암호화본으로 교체한다
기존 환경설정 사본은 복구 서버의 암호화 자격증명에 보관하며 DB 백업에서 제외한다
복구 서버의 verify_backup_bundle.py는 암호화 tar 입력을 검사하고 선택한 SQL 백업을 네트워크 없는 tmpfs PostgreSQL에 복원한다
복원한 런타임 비밀값과 KOTH 설정 이력의 암호문을 모두 복호화한 후 임시 DB를 제거한다
운영 DB를 직접 덮어쓰는 복원은 이 도구의 기능에 포함하지 않는다

## 서비스 키 교체

키의 교체 주기는 최대 90일이며 유출 의심 시 즉시 교체한다
교체 전 암호화 백업과 복구 키 보관 상태를 확인한다
새 Fernet 키를 첫 번째에 두고 이전 키를 뒤에 둔 암호화 자격증명을 준비한다
자격증명 동기화 후 새 설정을 사용하는 작업자에서 activate_service_key를 실행한다
runtime 목적에는 reencrypt 옵션을 사용한다
RuntimeSecret과 KothEnvironmentVersion 전체 행의 재암호화와 새 키 단독 복호화가 한 트랜잭션 안에서 성공해야 활성 키를 전환한다
실패하면 암호문과 활성 버전 및 감사 기록을 모두 되돌린다
전환 후 이전 키를 사용하는 작업자는 발급과 복호화 요청에서 503으로 차단된다
구 백업의 복원과 복호화를 확인한 뒤 이전 키를 운영 자격증명에서 제거한다
이전 키는 해당 키로 암호화한 백업의 보관 기간이 끝날 때까지 복구 서버에서만 보존한다

KOTH 키 전환은 [TC-613의 교체 절차](service-key-rotation.md)에 따라 rotate_koth_team_token_key로 수행하며 기대 버전과 작업 UUID를 함께 지정한다
activate_service_key의 koth 목적도 같은 필수 인자를 받아 동일한 KOTH 등록부와 감사 영수증을 사용한다
기존 KOTH ServiceKeyState와 폐기 이력은 인계 및 동기화하며 runtime 목적의 재암호화 등록부와 구분한다
이전 키의 토큰은 재조회 전에도 검증을 통과하지 못하며 구 키 작업자의 재발급도 차단된다
폐기한 버전은 명령으로 재활성화할 수 없으며 롤백할 때도 새 키 버전을 사용한다
발급된 게임 세션 자체의 종료 정책은 각 게임의 인증·회수 경로도 함께 확인한다

교체 명령에는 purpose와 actor 및 reason을 필수로 지정한다
ServiceKeyRotation은 이전 버전과 새 버전 및 수행자와 사유와 재암호화 건수 및 시각을 보존한다
키와 원문 토큰은 감사 기록에 저장하지 않는다
JWT 키를 교체하면 기존 access 및 refresh 토큰은 거절되어 재로그인이 필요하다
검증된 보안 세대보다 오래된 백엔드의 배포는 배포 스크립트에서 거절한다

## 복구 원칙

적용 전 Compose와 비밀값은 복구 서버에 암호화하여 보존한다
TLS 장애 시 검증된 인증서와 설정을 복원하고 서비스별로 재생성한다
키 교체가 완료된 후에는 구 앱 키로 되돌리지 않고 새 키를 사용하는 검증된 이미지로 복구한다
키 교체 및 인증서의 다음 기한은 운영 점검 기록에 남기고 기한이 지나면 보안 점검을 실패 처리한다
