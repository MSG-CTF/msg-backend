# 동시 로그인 처리

컨테이너 내부 nginx가 로그인 요청을 전용 Gunicorn 작업자로 보낸다
일반 API는 기존 작업자를 사용한다
로그인 대기 중에도 게임 인증·조회 요청이 같은 대기열에 묶이지 않도록 분리한다
외부 포트와 API 주소, Argon2 설정, 계정별 요청 제한은 유지한다

| 설정 | 기본값 | 범위 |
|---|---|---|
| WEB_CONCURRENCY | 2 | 일반 API 작업자 1–32개 |
| GUNICORN_THREADS | 4 | 일반 API 작업자당 스레드 1–64개 |
| LOGIN_WEB_CONCURRENCY | 2 | 로그인 작업자 1–8개, 작업자당 스레드 1개 |

기본 설정에서 로그인 해시는 동시에 2개를 계산한다
비밀번호 캐시나 해시 강도 변경은 사용하지 않는다
접속 IP를 차단하거나 계정을 정지하는 기능도 추가하지 않는다
로그인 본문은 8KiB까지 받고, 전체 본문을 받은 뒤 로그인 작업자에 전달한다
느리게 보내는 본문이 비밀번호 검증 작업자를 점유하지 않도록 처리한다

두 작업자 프로세스가 모두 기동된 뒤에 nginx를 시작한다
기동 확인 경로는 내부 소켓에서만 사용하며 외부에서는 404를 반환한다
DB와 Redis의 상태는 기존 /healthz에서 계속 확인한다
일반 API 작업자, 로그인 작업자 또는 nginx가 중단되면 컨테이너를 실패 상태로 종료한다
기존 컨테이너 재시작 정책과 배포 상태 확인을 그대로 사용한다

이 변경은 CPU 코어를 늘리지 않는다
로그인 작업자 수를 늘리기 전에는 CPU·메모리와 로그인 중 일반 API 지연을 함께 확인한다
