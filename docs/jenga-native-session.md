# Jenga 일반 세션 확인

일반 팀을 정지하고 문제 토큰을 회수해도 출제자 서버의 기존 Flask 쿠키로 상태 조회와 전략 중지를 요청할 수 있었다
게임 코드를 바꾸지 않고 공개 접속 경로에 세션 확인을 추가한다

백엔드는 현재 적용된 Jenga 환경변수 버전의 SESSION_SECRET으로 원본 쿠키 서명을 확인한다
현재 팀의 정지 상태와 해당 문제의 토큰을 확인하고 처음 확인한 토큰과 연결한다
토큰 회수·교체나 팀 정지를 확인한 쿠키는 다시 허용하지 않는다
서명 검증 후 압축 해제 크기도 제한하고 DB·캐시·비밀값 조회 실패 시 요청을 차단한다
서명에 들어 있는 팀 ID를 따로 신뢰하거나 출제자 서버에 새 쿠키 형식을 요구하지 않는다

배포 시 백엔드 API를 먼저 올린 뒤 deploy/koth_jenga_session_gateway.py의 guard_jenga_sessions로 Jenga의 Caddy 설정을 갱신한다
공개된 게임의 /state·/place·/strategy 요청 앞에 forward_auth를 추가한다
로그인·첫 화면·정적 파일, 기존 내부 점수 경로와 출발지 제한은 유지한다
관리자 미리보기 쿠키가 있으면 기존 미리보기 검증 경로를 사용한다

임시 QA를 운영 중이면 현재 Caddyfile과 예약 복구용 original.Caddyfile 모두 같은 함수로 처리하고 예약 복구 상태의 두 해시도 갱신한다
Caddy validate와 기존 close.py --check를 통과한 다음 설정을 적용한다
11월 6일 자동 잠금 시각이나 대회 공개 구간을 변경할 필요는 없다

이미 발급된 원본 쿠키는 첫 확인 때 현재 토큰과 연결한다
Flask 쿠키 시각은 초 단위라 배포 이전 쿠키의 최초 확인에는 토큰 발급 시각과 최대 1초의 구분 한계가 있다
연결된 세션은 토큰 ID·해시·발급 시각 변경을 그대로 비교한다
팀 정지 여부는 매 요청 DB에서 확인하며 성공 결과를 캐시하지 않는다
