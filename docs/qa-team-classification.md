QA팀 자동 분류

테스트팀 UUID는 인증 토큰과 분리된 영구 분류 기록으로 저장한다
관리자 팀 목록, 게임 참가팀 목록, KOTH 참가 수와 점수 지급은 같은 기록을 사용한다
팀이나 미리보기 토큰을 지워도 UUID 분류는 남아 게임에 남은 QA 기록을 제외한다
이 기록은 로그인이나 게임 접속 권한을 만들지 않는다

기존 자동 생성 도구의 QA 전용 이름을 예약한다

    QA12-ROLLOUT-f60b7620-0
    QA12-LIFECYCLE-16bd5bf8-11

형식은 QA와 숫자, 영문 작업명, 8자리 16진수 배치 식별자, 숫자 인덱스를 붙임표로 연결한 이름이다
작업명에는 영문자, 숫자, 밑줄과 붙임표를 허용하고 대소문자는 구분하지 않는다
이 전체 형식이 맞는 경우만 자동 분류하며 QA나 테스트라는 단어가 포함됐다는 이유로 일반 참가팀을 제외하지 않는다
이 형식은 QA 전용이므로 공식 참가팀 이름으로 사용하지 않는다

ORM, 대량 생성, 관리자 계정 생성 API와 직접 SQL 모두 실제 팀 삽입과 같은 트랜잭션에서 분류한다
충돌로 무시된 삽입은 기존 공식팀을 분류하지 않는다
팀을 새 UUID로 다시 생성하면 그 UUID도 자동 등록되며 QA 이름을 변경해도 분류는 유지된다
일반 팀 생성 경로는 기존대로 공식팀을 만든다

예약 이름을 쓰지 않는 QA 도구는 다음 생성 함수를 사용한다

    Team.objects.create_qa_team(team_name="운영 회귀 전용")

생성과 분류는 함께 커밋되며 분류 실패나 상위 트랜잭션 실패 때 둘 다 되돌린다
KOTH 문제가 아직 없어도 생성할 수 있고 미리보기 인증 토큰을 발급하지 않는다

배포에는 accounts의 0004_test_team_identity 마이그레이션이 필요하다
기존 미리보기 UUID와 예약 이름의 QA UUID만 초기 분류에 반영하며 팀, 계정, 비밀번호, 소속과 점수 필드는 변경하지 않는다
기존 미리보기 표식도 삭제하지 않으며 이후 새로 등록된 미리보기 UUID도 영구 분류에 함께 저장한다
DB 마이그레이션은 정상 배포 전에 적용하고 이전 앱으로 복구할 때도 영구 분류 기록을 삭제하지 않는다
